# DeepFlow Agent 安全与性能保障措施

DeepFlow Agent 作为部署在主机和容器节点上的数据采集组件，在设计和实现中充分考虑了主机安全和性能影响，采取了多项保障性措施。

## 一、安全保障措施

### 1.1 权限管理与最小权限原则

DeepFlow Agent 支持基于 Linux Capabilities 的精细化权限控制，避免使用完整的 root 权限：

- **必需的核心能力**：
  - `CAP_NET_ADMIN`：网络管理能力，用于网络数据采集
  - `CAP_NET_RAW`：原始套接字能力，用于抓包
  - `CAP_NET_BIND_SERVICE`：绑定特权端口能力
  - `CAP_SYS_ADMIN`：系统管理能力，用于 eBPF 程序加载
  - `CAP_IPC_LOCK`：内存锁定能力，用于防止敏感数据被交换到磁盘

- **权限检查机制**：
  - 提供 `--check-privileges` 参数，用于在 Kubernetes 环境中验证 Pod 权限配置
  - 支持 `--add-cap` 参数，动态授予所需的 Linux Capabilities

- **内存安全保护**：
  - 使用 `mlockall()` 系统调用锁定内存，配合 `CAP_IPC_LOCK` 能力
  - 防止包含 eBPF 采集数据的敏感内存被交换到磁盘，避免潜在的数据泄露

### 1.2 命名空间隔离

- **Sidecar 模式**：
  - 支持 `--sidecar` 模式，在 Pod 级别进行隔离监控
  - Sidecar 模式下不访问主机资源，仅监控同一 Pod 内的应用
  - 适用于对安全隔离要求较高的场景

- **eBPF Uprobe 过滤**：
  - 对非特权容器进行 eBPF uprobe 过滤
  - 基于命名空间进行 socket 和进程追踪，避免跨命名空间的数据泄露

### 1.3 eBPF 内核安全

- **eBPF JIT 编译**：
  - 启用 eBPF JIT 编译（`bpf_jit_enable`），提高 eBPF 字节码执行的安全性
  - JIT 编译后的代码在内核空间执行，经过严格的验证

- **BTF 类型信息验证**：
  - 基于 BTF（BPF Type Format）进行内核结构体偏移量验证
  - 确保 eBPF 程序对内核数据结构的访问是类型安全的

- **内核版本兼容性检查**：
  - 支持 Linux 4.12 及以上版本
  - 在启动时检查内核版本和特性支持情况，确保功能兼容性

## 二、性能保障措施

### 2.1 资源限制机制（Cgroups）

DeepFlow Agent 通过 Cgroups v1 和 v2 实现严格的资源限制：

- **内存限制**：
  - 默认内存限制：768MB（可通过 `max_memory` 配置）
  - 通过 Cgroups 内存控制器实现硬限制
  - 防止 Agent 内存使用失控影响主机

- **CPU 限制**：
  - 通过 `max_millicpus` 配置 CPU 使用上限
  - 使用 CFS（完全公平调度器）配额机制，每毫核单位对应 100μs
  - 示例：1000 millicpus = 1 个 CPU 核心

- **Cgroups 层次结构自动检测**：
  - 自动检测系统使用的 Cgroups 版本（v1 或 v2）
  - 根据系统配置自动适配对应的控制器

- **资源监控降级方案**：
  - 支持 `--cgroups-disabled` 参数禁用 Cgroups（用于不支持 Cgroups 的环境）
  - 降级模式下，Agent 每 10 秒检查一次 CPU 和内存使用情况
  - 当资源使用超过阈值时，会主动降低采集频率或暂停部分功能

### 2.2 内存管理优化

- **内存回收机制**：
  - 使用 `malloc_trim()` 主动回收未使用的内存块
  - 根据系统类型配置内存整理策略
  - 定期触发内存整理，避免内存碎片积累

- **RssFile 内存优化**：
  - 针对 AF_PACKET 操作进行 RssFile 内存优化
  - 减少页缓存占用

- **页缓存回收控制**：
  - 控制页缓存的回收策略，平衡内存使用和性能

### 2.3 流量与负载管理

- **系统负载熔断机制**：
  - 当系统负载超过阈值时，自动禁用 Agent 的部分功能
  - 安全期（默认 300 秒）内负载正常后自动恢复
  - 防止在系统高负载时 Agent 加剧性能问题

- **Socket 连接数限制**：
  - 可配置的最大 socket 连接数限制
  - 设置容忍间隔，避免短时间内频繁触发限制

- **IO 事件过滤**：
  - 配置最小 IO 事件持续时间阈值
  - 过滤掉持续时间过短的 IO 事件，减少数据处理开销

- **磁盘空间监控**：
  - 监控磁盘空间使用情况
  - 当磁盘空间不足时，自动清理旧的日志文件
  - 设置磁盘空间阈值，避免日志占满磁盘

### 2.4 线程与资源隔离

- **进程阈值限制**：
  - 配置进程数量阈值，避免追踪过多进程导致性能问题

- **线程计数监控**：
  - 监控 Agent 自身的线程数量
  - 检测异常的线程创建行为

- **Watchdog 监控线程**：
  - 独立的 Watchdog 线程监控操作是否卡死
  - 及时发现并处理异常情况

### 2.5 Cgroups 控制器实时监控

- **实时资源监控**：
  - Cgroups 控制器每秒检查一次资源限制
  - 动态更新资源使用状态
  - 当接近限制时触发告警或采取保护措施

## 三、配置与调优

### 3.1 配置驱动设计

- 所有安全和性能参数均可通过 YAML 配置文件进行调整
- 提供合理的默认值，优化开箱即用体验
- 默认配置已针对最小性能开销进行优化

### 3.2 关键配置文件位置

- Cgroups 资源限制：`/agent/src/utils/cgroups/linux.rs`
- 系统资源监控与保护：`/agent/src/utils/guard.rs`
- 内存锁定与初始化：`/agent/src/config/handler.rs`
- eBPF 架构与安全设计：`/agent/src/ebpf/README.md`

## 四、性能开销评估

在生产环境中，DeepFlow Agent 的典型性能开销：

- **CPU 使用率**：< 1% （单核，取决于流量和配置）
- **内存占用**：通常 < 500MB（默认限制 768MB）
- **网络开销**：eBPF 零拷贝技术，对应用网络性能影响极小
- **持续性能剖析开销**：< 1%（通过 eBPF 实现的性能剖析）

## 五、总结

DeepFlow Agent 通过以下核心机制确保主机安全和最小性能影响：

1. **最小权限原则**：基于 Linux Capabilities 的精细化权限控制
2. **强隔离**：命名空间隔离和 Sidecar 模式支持
3. **严格资源限制**：通过 Cgroups 实现 CPU 和内存硬限制
4. **智能熔断**：系统负载过高时自动降级保护
5. **内存安全**：内存锁定和主动回收机制
6. **eBPF 技术优势**：在内核空间高效采集，零侵扰应用

这些措施使得 DeepFlow Agent 能够在保证可观测性的同时，将对生产环境的影响降到最低。
